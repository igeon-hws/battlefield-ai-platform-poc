# UI 디자인 가이드: Agentic Battlefield Intelligence Platform

- 문서 상태: 디자인 제안 v0.4 — React UI·Python API 경계 반영
- 작성일: 2026-10-15
- 기준 문서: [PRD](./PRD.md)
- SDD 단계: Design

## 1. 디자인 방향

**지도 중심의 분석 작업 공간. 차콜 표면, 정돈된 정보 밀도, 선명한 상태 구분.**

Palantir GOTHAM과 Anduril LATTICE를 사용자가 제시한 시각적 레퍼런스로 삼는다. 본 문서의 색상, 치수, 레이아웃과 동작은 이 PoC를 위한 독자적인 제안이다. 해당 제품의 실제 디자인 토큰이나 내부 UI 사양을 의미하지 않는다.

- 지도와 객체가 화면의 중심을 차지한다. 제목이나 장식보다 현재 상황이 먼저 보인다.
- 패널은 단색 표면과 1px 구분선으로 나눈다. 깊이는 밝기 차이로 표현한다.
- 정보는 정렬, 간격, 글자 굵기로 계층을 만든다. 색은 선택과 상태 전달에 집중한다.
- 분석은 요약 → 근거 → 실행 상세 순서로 읽는다. Agent 실행 상태는 작업 흐름에 통합한다.
- 객체·이벤트·분석·방책 사이의 연결을 유지한다. 화면을 바꿔도 현재 선택과 분석 맥락을 잃지 않는다.

### 피해야 할 표현

| 항목 | 적용 규칙 |
| --- | --- |
| 장식용 그라데이션, 유리 효과, 네온 글로우 | 사용하지 않는다 |
| 보라·인디고 중심 AI 브랜딩 | 사용하지 않는다 |
| 큰 환영 문구, 중앙의 거대한 채팅 입력창 | 상황판의 첫 화면에 배치하지 않는다 |
| 반짝이 아이콘, 로봇 아바타, Powered by AI 배지 | 사용하지 않는다 |
| 모든 정보를 둥근 카드로 분할 | 관련 정보는 패널·행·구분선으로 묶는다 |
| 장식용 레이더 스캔, 지속 점멸, 타이핑 효과 | 사용하지 않는다 |
| 불필요한 3D, 홀로그램, 과도한 군사풍 장식 | 사용하지 않는다 |

### 프론트엔드 구현 경계

- 두 UI는 React·TypeScript·Vite 정적 앱으로 제안한다. 배포 시 각 Python FastAPI 서버가 해당 UI와 /api·SSE를 같은 출처로 제공한다.
- 브라우저는 지도·심벌·벡터 선·표시용 보간·선택 상태를 처리한다. 원천 이동·표시 벡터 끝점·거리/방위 계산·Agent 실행은 Python 서버가 담당한다.
- 개발 프록시는 Python API에 전달만 한다. API·Agent 로직과 비밀 키를 UI 코드에 두지 않는다.

## 2. 화면 구조

### 2.1 기본 작업 화면

데스크톱 기준으로 상단 바, 좌측 탐색 레일, 객체 패널, 지도, 우측 분석 패널을 배치한다.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 제품명 / 시나리오          모의 환경     C4I 연결 · 갱신 시각             │
├────┬─────────────┬───────────────────────────┬───────────────────────────┤
│탐색│ 객체 패널    │                           │ 분석 / 이력               │
│레일│ 검색·필터    │       상황 지도           │ 실행 원인·진행 상태        │
│    │ 객체 목록    │       객체·이동 방향      │ 분석 요약·근거             │
│    │ 선택 상세    │                           │ 실행 상세 / 방책 비교 열기 │
│    │             │                           ├───────────────────────────┤
│    │             │                           │ 자연어 질의 입력           │
├────┴─────────────┴───────────────────────────┴───────────────────────────┤
│ 최근 이벤트 스트립 · 이벤트 선택 시 관련 객체·분석으로 연결              │
└────────────────────────────────────────────────────────────────────────┘
```

| 영역 | 기준 |
| --- | --- |
| 상단 바 | 높이 48px, 제품명은 16px 이하. 모의 환경·연결 상태·갱신 시각 상시 표시 |
| 탐색 레일 | 폭 48px. 상황판·분석 이력 탐색, 아이콘에 툴팁과 접근 가능한 이름 제공 |
| 객체 패널 | 기본 256px, 접기 가능. 검색·목록과 선택 객체 요약 제공 |
| 지도 | 가변 폭, 기본 화면의 가장 큰 단일 영역. 최소 폭 480px 확보 |
| 분석 패널 | 기본 400px, 360–520px 범위 조절. 헤더·입력 고정, 본문 스크롤 |
| 이벤트 스트립 | 높이 36px. 최근 이벤트 요약과 전체 이력 진입점 제공 |

1440×900을 기본 설계 화면으로 사용한다. 1920×1080에서는 늘어난 공간을 지도와 분석 본문에 배분한다. 페이지 전체에 max-width를 두지 않는다.

### 2.2 방책 비교 화면

- 우측 패널의 `방책 3개 비교`로 진입한다.
- 상단 바와 탐색 레일을 유지하고 나머지 작업 영역을 비교 화면으로 전환한다.
- 비교 시 객체 패널은 접고 지도는 `지도 보기`로 전환 가능하게 한다. 선택 객체, 지도 위치, 분석 ID를 유지한다.
- 세 열을 같은 폭으로 배치한다. 채팅 패널 안에 좁은 카드 세 개를 넣지 않는다.
- `분석으로 돌아가기`를 누르면 이전 지도와 패널 상태로 복귀한다.
- 별도의 모달 확인 없이 선택 상태를 표시한다. 선택은 C4I 명령 실행을 뜻하지 않는다.

### 2.3 화면 폭과 확대 대응

- 1280–1439px: 객체 패널을 기본 접고 분석 패널은 360px로 유지한다.
- 1280px 미만 또는 브라우저 확대 시: 지도·분석을 탭으로 전환한다. 핵심 기능을 숨기지 않는다.
- 방책 비교는 열당 최소 300px, 간격 16px을 유지하며 폭이 부족하면 비교 영역만 가로 스크롤한다. 열 제목과 선택 상태를 식별할 수 있어야 한다.
- 모바일 전용 설계는 이번 제안의 우선 범위 밖이다. 작은 화면에서도 질의·결과·선택에는 접근 가능하게 한다.

### 색 사용 규칙

- 화면의 대부분은 무채색 계열로 유지한다. 강조 색으로 패널 전체를 채우지 않는다.
- 위험·실패와 선택은 다른 시각 요소로 구분한다. 위험 객체를 선택해도 위험 표식을 유지한다.
- 객체 소속과 시스템 상태는 별도 범례를 갖는다. 아군은 파란 직사각형, 적군은 붉은 마름모와 소속 텍스트로 구분하는 PoC 심벌을 제안한다. 미분류는 회색 원형을 사용한다. 운용 상태·갱신 지연·AI 위험 평가는 별도 표식과 레이블이다.
- 색만으로 의미를 전달하지 않는다. 상태명, 심벌, 선 종류를 함께 사용한다.
- `border-subtle`은 장식 구분선에만 사용한다. 조작 영역의 식별과 포커스에는 `border-control` 또는 `accent`를 사용한다.

## 4. 타이포그래피와 공간

### 글꼴

- UI: Pretendard → Noto Sans KR → system-ui → sans-serif 순서의 폴백.
- 식별자·좌표·시각·수치: ui-monospace → Consolas → monospace. 숫자는 tabular-nums를 사용한다.
- 한글은 기본 자간을 유지한다. 작은 영문 섹션 레이블에만 최대 0.04em 자간을 허용한다.

| 용도 | 크기 / 행간 | 굵기 |
| --- | --- | --- |
| 작업 화면 제목 | 18 / 26px | 600 |
| 패널 제목 | 14 / 20px | 600 |
| 본문·분석 결과 | 14 / 22px | 400 |
| 목록·컨트롤 | 13 / 20px | 400–500 |
| 보조 정보·타임스탬프 | 12 / 18px | 400 |
| 주요 수치 | 20 / 28px | 600 |

- 간격 단위: 4, 8, 12, 16, 24, 32px. 패널 패딩은 기본 16px, 조밀한 목록은 12px.
- 모서리: 패널 0px, 입력·버튼 4px, 팝오버 6px. 원형은 상태 점과 지도 선택 링 등 의미가 있는 경우에 사용한다.
- 그림자: 일반 패널에는 사용하지 않는다. 떠 있는 메뉴에만 약한 단일 그림자를 허용한다.
- 행 높이: 조밀한 데이터 목록 36px, 보조 설명이 있는 목록 52px 이상.

## 5. 상황 지도와 객체

### 지도 표현

- 저채도 다크 2D 지도를 기본 방향으로 한다. 도로·지형·경계선은 객체보다 낮은 대비로 표시한다.
- 기본 레이어는 단순하게 유지한다. 객체, 이름, 이동 벡터, 이동 이력은 각각 표시 여부를 바꿀 수 있게 한다.
- 북쪽, 축척, 좌표 기준, 마지막 데이터 시각을 확인할 수 있게 한다. 지도 출처 표기가 필요한 경우 가리지 않는다.
- 실제 지리 배경 지도를 사용한다. 원천 좌표는 WGS84 경도·위도이며 기본 엔진은 MapLibre GL JS로 제안한다. 임의 평면 상황도는 기본 화면을 대체하지 않는다.
- 좌표 레이블에는 위도·경도를 명시하고 GeoJSON의 내부 배열은 경도·위도 순서를 유지한다. 지도 데이터·축척·출처를 확인할 수 있게 한다.
- 배경 지도 로딩 실패와 C4I 연결 실패를 구분한다. 배경 장애 시에도 보유한 객체·목록·좌표와 복구 동작을 제공한다.

### 객체와 선택

- 기본 심벌은 16–20px, 선택 링은 28–32px. 선택 심벌을 이동 방향 화살표와 구분한다.
- 적아 심벌은 형태를 유지하고 방향 화살표를 따로 회전시킨다. 흰 선택 링으로 선택을 표현하며 적아 색을 선택 색으로 덮어쓰지 않는다. 두 시스템에서 같은 소속 심벌을 사용한다.
- 소속·유형·가용 상태 필터와 범례를 제공한다. 필터는 함께 적용하며 선택 조건과 초기화 동작을 표시한다. 객체 상세에서 소속·유형·운용 상태·가용 상태/사유·위도·경도·속도(m/s)·방위(도)를 각각 확인한다.
- 목록에는 `아군 · 탱크 · 가용`처럼 세 속성을 구분해 표시한다. 탱크·함정은 적아 외곽 심벌 안의 서로 다른 픽토그램과 유형명으로 구분하고 적아 색·형태 규칙은 유지한다.
- 목록 머리의 `전체 일치 12 · 현재 10개 표시`처럼 원천 전체 일치 수와 현재 페이지 수를 구분한다. 집계에는 적용 필터·영역·기준 시각을 표시한다.
- 가용은 텍스트와 작은 상태 표식으로 표현한다. `미확인`을 `가용 불가`와 합치지 않으며 소속 색을 가용 색으로 덮어쓰지 않는다. 정지 객체도 가용일 수 있다.
- 초기 질문 예시에 `가용 아군 탱크 보여줘`, `적 탱크는 몇 대야?`를 포함한다. 답변의 목록·수량은 MCP 근거와 연결한다.
- 레이블은 식별자와 필요한 상태만 표시한다. 이름 충돌 시 선택 객체를 우선하고 나머지는 확대·호버로 노출한다.
- 객체 클릭 시 지도와 목록의 선택 상태가 동기화되고 객체 요약이 열린다. 키보드로 목록에서 같은 정보를 확인할 수 있어야 한다.
- 객체 선택만으로 지도를 강제 이동하지 않는다. `지도에서 보기`와 `추적`을 명시적으로 제공한다.
- 추적 중 사용자가 지도를 직접 이동하면 추적을 해제하고 상태를 표시한다.

### 이동과 최신성

- 원천 데이터의 매초 갱신은 PRD 기준을 따른다. 갱신 사이의 시각적 보간은 허용하되 새 데이터처럼 취급하지 않는다.
- 데이터가 멈추면 보간도 멈춘다. 임의로 미래 위치를 계속 이동시키지 않는다.
- 이동 벡터는 현 속도 유지 시 30초 동안의 거리·방향을 표시하는 안을 제안한다. 범례에 `현재 속도 × 30초 · 예측 아님`을 표시하고 궤적과 선 종류를 구분한다. 끝점은 Python 서버가 제공한 displayVector를 사용한다. 속도 0은 벡터 선을 숨기고 `정지 · 0 m/s`로 표시한다.
- 지도 회전 시 이동 화살표와 선은 지리 방향을 유지한다. 확대·축소 시 심벌 크기는 유지하고 벡터 길이는 지리 거리에 따라 변한다.
- 객체의 마지막 원천 갱신 시각과 연결 상태를 구분한다. 오래된 데이터는 점선 외곽과 `갱신 지연` 텍스트로 표시한다.
- 지연 판정 임계값은 PRD·아키텍처에서 정한다. UI 가이드에서 임의의 확정값을 만들지 않는다.

## 6. 분석 패널과 실행 이력

### 정보 순서

1. 실행 원인: `사용자 질의` 또는 `C4I 이벤트`, 시각, 관련 객체.
2. 실행 상태: 대기·실행 중·완료·일부 실패·실패.
3. 분석 요약: 핵심 변화와 확인할 사항을 짧게 표시.
4. 근거: 원천 데이터 식별자, 조회 시각, 해당 근거로 이동하는 링크.
5. 방책 비교 진입점과 접힌 실행 상세.

사용자 질의는 작은 텍스트 블록, 답변은 구조화된 본문으로 표시한다. 큰 말풍선과 장식용 Agent 아바타는 사용하지 않는다. 처음 사용 시 짧은 예시 질문 2–3개만 제공한다.

### 자연어 입력

- 분석 패널 하단에 2–5줄 입력 영역과 `질의 실행` 버튼을 둔다.
- Enter로 전송, Shift+Enter로 줄바꿈한다. 한글 IME 조합 중 Enter는 전송하지 않는다.
- 입력 내용은 실패 시 유지한다. 같은 대화의 실행 중에는 새 질의 제출을 막고 작성은 허용한다. 완료 후 후속 질문을 제출한다.
- 스트리밍 결과를 읽는 동안 사용자가 위로 스크롤하면 자동 스크롤을 멈추고 `최신 내용` 버튼을 제공한다.

### 단일 Agent와 MCP 실행 상세

- 단일 `상황 분석 Agent`의 loop를 시간순으로 표시한다. 모델 호출·Tool 실행·결과 수신·최종 응답을 구분한다.
- 일반 질문의 도구 없는 직접 답변도 정상 완료 상태다. 수행하지 않은 호출을 대기·실패로 표시하지 않는다.
- 각 Tool 행에는 도구명·상태·작업 요약·시각·소요 시간을 표시한다. 펼치면 입력·응답·오류·근거와 snapshot 기준을 확인한다.
- 조회 결과에 따라 추가된 실제 호출을 표시한다. 고정된 Agent 역할·계획 버전·위임 그래프는 표시하지 않는다.
- 재시도·입력 교정·실행 제한 종료는 실제 상태와 시도로 남긴다. 모델 내부 사고 과정은 노출하지 않는다.
- 실패한 호출과 전체 결과의 실패·부분 결과를 구분한다. 실패한 호출을 완료 아이콘으로 바꾸지 않는다.
- 원본 구조화 응답은 접힌 상세로 제공한다. 기본 화면에는 요약과 근거를 우선한다.

### 간단한 대화 맥락

- 같은 분석 패널에서 질문·답변과 후속 질의를 이어간다. 새 대화 동작으로 이전 맥락을 비울 수 있다.
- 각 답변에 분석 시각과 run 참조를 유지한다. 후속 질문이 현재 상태를 물으면 새 데이터 조회 후 새 기준 시각을 표시한다.
- 최근 대화 범위가 제한됨을 필요할 때 짧게 안내한다. 분기 대화·장기 기억 설정·Agent별 대화방은 제공하지 않는다.
- 자동 이벤트 분석은 새 결과 알림으로 표시하고 사용자가 읽는 대화에 자동 끼워 넣지 않는다.

### 이벤트와 읽기 맥락

- 이벤트 스트립은 최근 발생 요약만 제공한다. 전체 이력은 필터 가능한 목록에서 확인한다.
- 새 이벤트가 도착해도 현재 보고 있는 분석을 바꾸지 않는다. `새 분석 2건`처럼 새 항목을 알린다.
- 이벤트 선택 시 관련 객체와 분석 실행을 연결한다. 연결된 분석이 없으면 `분석 대기` 등 실제 상태를 표시한다.
- 자동 실행 여부, 중복 이벤트 병합 여부는 실행 정책에서 정하며 UI는 그 결과를 정확히 반영한다.

## 7. 세 가지 방책 비교

```text
분석 요약 · 기준 시각 · 근거 보기                     분석으로 돌아가기
┌──────────────────┬──────────────────┬──────────────────┐
│ 방책 01 / 제목    │ 방책 02 / 제목    │ 방책 03 / 제목    │
│ 요약             │ 요약             │ 요약             │
├──────────────────┼──────────────────┼──────────────────┤
│ 근거             │ 근거             │ 근거             │
│ 기대 효과        │ 기대 효과        │ 기대 효과        │
│ 위험·제약        │ 위험·제약        │ 위험·제약        │
├──────────────────┼──────────────────┼──────────────────┤
│ 이 방책 선택     │ 이 방책 선택     │ 이 방책 선택     │
└──────────────────┴──────────────────┴──────────────────┘
```

- 세 열은 동일한 정보 순서와 위계를 사용한다. 비교 항목의 행을 맞추고 본문은 비교 영역 전체에서 세로 스크롤한다.
- 제목과 선택 영역은 고정하고 각 열의 개별 세로 스크롤은 만들지 않는다.
- 선택 전에는 어느 방책도 미리 선택하지 않는다. 근거 없는 `최선`·`추천 1위` 배지를 붙이지 않는다.
- 선택은 radio group과 같은 단일 선택 의미를 갖는다. `이 방책 선택` 동작 후 선택 표시를 즉시 제공한다.
- 선택된 열은 accent 외곽선, 연한 선택 배경, 체크 아이콘과 `선택됨`으로 구분한다.
- 선택 기록 저장이 있다면 저장 중·저장됨·저장 실패를 구분한다. 실패 시 저장된 것처럼 표시하지 않는다.
- 선택 변경 가능 여부와 기록 정책은 아키텍처의 선택 정책을 검토하여 확정한다. 새 분석 결과에는 이전 선택을 자동 승계하지 않는다.
- 세 방책이 모두 준비되기 전에는 `방책 생성 중` 또는 실제 실패 상태를 표시한다. 부족한 방책을 임의의 문구로 채우지 않는다.
- 분석 기준 시각과 현재 상황의 시각을 함께 확인할 수 있게 한다. 이전 분석 결과를 실시간 분석처럼 표시하지 않는다.

## 8. 공통 컴포넌트

| 컴포넌트 | 규칙 |
| --- | --- |
| 기본 버튼 | 높이 32px 이상, radius 4px, 얇은 외곽선. 조작 영역 최소 32×32px |
| 주요 버튼 | accent 바탕 + background 색 텍스트. 패널 내 한 가지 주요 동작에 집중 |
| 보조 버튼 | 투명 또는 surface 바탕, text-primary, border-control |
| 위험 버튼 | 실제 파괴적 동작에만 사용. 분석 시작·방책 선택에 빨간 버튼 사용 금지 |
| 입력·검색 | 높이 36px 이상, 레이블 제공, placeholder만으로 용도 설명 금지 |
| 목록·테이블 | 좌측 텍스트, 우측 수치. 식별자·시각은 고정폭, 선택 행은 색과 표시선 병용 |
| 상태 배지 | 작은 심벌 + 텍스트. 상태별 거대한 색상 배경 사용 금지 |
| 탭 | 하단 표시선과 글자 굵기로 활성 상태 표시 |
| 툴팁 | 짧은 설명에 사용. 필수 정보나 선택 버튼을 숨기지 않는다 |
| 팝오버 | 필터·레이어·간단한 상세. Escape로 닫고 원래 컨트롤로 포커스 복귀 |
| 아이콘 | 일관된 SVG 계열, 16–20px, stroke 1.5–2px. 장식용 배경 원형 박스 생략 |

## 9. 상태·시각·문구

| 상황 | 표시와 동작 |
| --- | --- |
| 최초 로딩 | 패널 구조를 유지한 정적 skeleton + 로딩 텍스트 |
| 객체 없음 | `표시할 객체가 없습니다`와 데이터 연결·필터 확인 안내 |
| 필터 결과 없음 | `조건에 맞는 객체가 없습니다`와 필터 초기화 |
| C4I 연결 끊김 | 상단 연결 상태와 마지막 수신 시각 표시. 기존 데이터는 오래된 상태로 유지 |
| MCP 호출 실패 | 실패한 호출과 원인을 표시하고 재시도 가능 여부 안내 |
| Agent 실행 실패 | 실패 단계와 사용 가능한 부분 결과를 구분. 성공으로 표시하지 않음 |
| 방책 생성 실패 | 실패 상태와 재시도 동작. 세 열에 가짜 결과를 넣지 않음 |

- UI 문구는 한국어를 기본으로 한다. 객체 ID와 실제 도구명은 원문을 유지한다.
- Agent 표시명은 `상황 분석 Agent`로 통일한다. `상황 요약`, `위험 검토`, `방책`은 한 결과의 내용 구분이며 별도 Agent 실행을 뜻하지 않는다.
- 시각은 화면에 명시한 시간대로 일관되게 표시한다. 기본 제안은 KST(UTC+09:00), 같은 날은 HH:mm:ss, 상세에는 날짜 포함이다.
- 시뮬레이션 시각과 실제 수신·조회 시각이 다르면 각각 레이블을 붙인다.
- `완벽한 분석`, `AI가 모든 위협을 탐지` 같은 확정적 홍보 문구를 사용하지 않는다.
- 불확실성은 근거와 제한 사항으로 설명한다. 검증되지 않은 확률·신뢰도 점수를 장식처럼 표시하지 않는다.

## 10. 접근성과 모션

- 일반 텍스트 대비 4.5:1 이상, 큰 텍스트와 필수 UI 경계·심벌 대비 3:1 이상을 목표로 구현 시 검증한다.
- 모든 입력과 버튼에 키보드로 접근할 수 있어야 한다. 포커스는 accent 2px 외곽선과 2px 간격으로 표시한다.
- 지도 객체는 목록에서 동등한 데이터·선택 기능을 제공한다. 호버 정보는 포커스와 클릭으로도 접근 가능해야 한다.
- 상태 변경은 적절한 live region으로 알리되 매초 좌표 변화는 낭독하지 않는다.
- 색상 범례, 상태명, 심벌을 함께 사용한다. 위험과 연결 실패를 같은 색만으로 구별하지 않는다.
- hover·focus 전환은 120–160ms, 패널 전환은 최대 200ms. bounce·glow·자동 점멸은 사용하지 않는다.
- prefers-reduced-motion에서는 전환과 이동 보간을 줄이거나 끈다. 원천 데이터 갱신은 유지한다.

## 11. Mock C4I 화면과의 관계

- 분석형 플랫폼과 별개의 외부 시스템임을 제품명과 `Mock C4I · 모의 환경` 표기로 구분한다.
- 객체 식별자, 좌표·속도 단위, 상태 명칭은 양쪽 화면에서 일치시킨다.
- Mock C4I는 객체 이동·상태·이벤트 조작에 집중하고 분석 패널과 방책 비교는 분석형 플랫폼에 둔다.
- 조작 UI의 구체적 범위는 후속 시나리오 설계에서 확정한다. 이 문서는 새 C4I 제어 기능을 추가로 확정하지 않는다.

## 12. 구현 전·후 확인 기준

| PRD 연결 | UI 확인 항목 |
| --- | --- |
| FR-01 / FR-02 | 객체 식별·선택·이동 방향과 목록 동기화 확인 |
| FR-03 | 갱신 시각·연결 상태·오래된 데이터 구분 |
| FR-04 | 자연어 질의·진행 상태·답변·근거 탐색 |
| FR-05 | 이벤트 원인 표시와 새 자동 분석 알림 |
| FR-06 / FR-07 | 단일 Agent loop·MCP 호출 입력/응답/오류·후속 질문과 새 기준 시각 확인 |
| FR-09 | 유형·소속·가용 필터 조합·탱크/함정 구분·전체 일치 수·미확인 상태 확인 |
| FR-08 | 세 열 동시 비교·동일 위계·단일 선택·선택 상태 확인 |
| 공통 | 1440×900 및 1280×800, 키보드, 확대, 대비, reduced motion 검증. 통합 E2E는 Playwright Python 사용 |

본 문서는 Design 단계의 제안이다. 실제 지리 지도·적아 객체는 사용자 요구사항이며, 색상·심벌 세부와 배치는 검토 후 구현 기준으로 확정한다. 이벤트 정책·실시간 임계값·방책 선택 저장 정책은 PRD와 아키텍처 결정에 따른다.
