## 고도화 요구사항 — v0.6 우선 적용

기존 PoC의 목적을 유지하면서, 서로 다른 원천 데이터를 **조직이 사용하는 개념과 관계로 일관되게 해석하는 Semantic Layer의 효용**을 검증한다. Ontology는 개념·관계·매핑 규칙, Knowledge Graph는 검증된 관계의 저장·탐색, MCP는 Agent 접근 인터페이스다. 세 가지를 같은 기능으로 취급하지 않는다.

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| FR-10 | Mock ATCIS(지상), Mock KNCCS(해상)의 독립 제공 | 각각 UI·API·DB·시뮬레이터·시나리오와 별도 MCP를 갖는다. 상대 체계·Graph·플랫폼 없이 실행된다. 실제 체계 내부 구조를 재현하지 않는다. |
| FR-11 | 이종 원천 계약과 통합 상황판 | ID·조직·유형·상태·좌표/속도 표현이 다른 가상 스키마를 제공한다. 플랫폼은 명시적 어댑터로 표시 형식을 정규화하고 출처·원천 ID를 보존한다. |
| FR-12 | Ontology와 근거 기반 관계 | Unit, Equipment, System, Observation, SourceRecord 및 SUBORDINATE_TO·ASSIGNED_TO·REFERS_TO를 정의한다. 모든 관계에 원천 참조·매핑 규칙·버전을 연결한다. |
| FR-13 | Python Graph Builder와 Neo4j | 공식 Python 드라이버로 초기 구축·안정적 관계 변경 동기화를 수행한다. 재실행 중복, 중간 실패, 원천 reset·이벤트 공백을 처리하고 검증된 build만 공개한다. 매초 이동은 Graph에 복제하지 않는다. |
| FR-14 | 재사용 가능한 Semantic API/MCP | Agent 외 서비스도 동일한 Python 도메인 로직을 HTTP API로 사용한다. MCP는 읽기 어댑터이며 임의 Cypher·Graph 쓰기 도구를 제공하지 않는다. |
| FR-15 | 결정론적 Entity Resolution·불일치 설명 | 원천 복합 ID, 명시적 공통 식별자 또는 검증된 crosswalk로 연결한다. 이름 유사성만으로 병합하지 않는다. 상충하는 원천 값·관측 시각·판별 근거를 보존한다. |
| FR-16 | Semantic OFF/ON 실행 격리 | OFF는 원천 MCP와 일반 계산만 사용하며 Semantic 해석·관계 해소·동일성 판정 helper의 간접 호출도 금지한다. ON은 Semantic MCP의 검증된 해석을 추가 사용한다. 공유 집계/도구 설명/표시 projection/이전 정책 대화를 통한 해석 유입도 차단한다. 단일 native loop와 discovery를 유지한다. |
| FR-17 | 재현 가능한 쌍 비교 | 동일 질문·두 원천의 고정 snapshot 집합·모델 설정으로 두 run을 생성한다. Graph도 해당 snapshot의 안정 정보로 구축한 버전을 고정한다. 답변·도구·근거·오류·비용/시간을 비교한다. |
| FR-18 | 시연과 평가 | semantic-demo-v2의 조직 탐색·이종 통합·동일 객체 연결/중복 방지 세 시나리오를 제공한다. 같은 객체의 기본 상태·배속은 상충하지 않는다. 충돌/동명/누락은 별도 negative fixture에서만 검증한다. 독립 gold와 모드별 평가를 사용하며 OFF의 근거 있는 모델 추론 성공도 허용한다. |

### 고도화 범위와 성공 기준

- “모의 1사단의 가용한 탱크”: 예하 조직을 포함한 소속 장비 범위를 관계로 확인하고, 고정 원천 snapshot의 명시적 가용 상태로 목록·수를 산출한다.
- “모의 1사단과 모의 1함대의 가용 전력”: 두 체계의 조직 범위를 통합하되 유형별 수와 원천 레코드 수/중복 제거 객체 수를 구분한다. 전투력 점수로 환산하지 않는다.
- 동일 객체: 서로 다른 원천 ID를 명시적 근거로 연결하고 중복 집계를 방지한다. 기본 UAV는 양쪽 가용이며 B11/S11의 비전속 공동지원 역할을 원천에 명시한다. 기본 통합값은 raw 8/unique 7/가용 4/불가 2/미확인 1/충돌 0이다. 실제 오류 상태를 숨기거나 임의로 한 원천을 정답으로 선택하지 않는다.
- ON/OFF 결과를 나란히 열고, 같은 기준 데이터인지 확인한 뒤 조직 경로·동일성 근거·원천 조회·집계의 차이를 설명할 수 있다.
- Graph 또는 한 원천 장애가 나머지 체계의 독립 실행을 막지 않는다. 불완전한 비교는 완료된 비교나 ON의 우수성으로 표시하지 않는다.

단일 원천의 FR-01~FR-09 기능은 두 체계 및 플랫폼에 재사용한다. 아래의 `Mock C4I`/`MCP Server` 단수 표현은 기존 구현 기준이다. v0.6에서는 원천별로 적용한다. 기존 120개 분포는 회귀용 기준 시나리오이며 두 체계의 새 기본 분포를 확정하는 수치가 아니다. 소규모 비교 fixture와 지도 규모 검증 fixture는 분리한다.

설계: [서비스 경계](./SEMANTIC_ARCHITECTURE.md), [Ontology·매핑](./ONTOLOGY_DESIGN.md), [시연·평가](./SEMANTIC_DEMO.md). 이번 범위에서 RDF/OWL 추론 엔진, 벡터 DB/RAG, LLM Graph 생성, 새로운 Agent 프레임워크·Multi-Agent는 도입하지 않는다.

## 1. 목표

외부 모의 지휘통제체계(C4I)의 상황 정보를 분석형 AI 플랫폼에 통합하고, LLM Agent가 MCP를 통해 해당 체계의 정보를 조회하여 상황 인지, 변화 분석 및 의사결정 지원을 수행하는 PoC를 구현한다.

움직이는 객체와 상태 변경을 상황판에 반영하고, 사용자 질의와 C4I 이벤트라는 두 진입점에서 단일 동적 분석 Agent가 분석을 수행하는 전체 흐름을 검증한다. 사용자는 분석 근거와 도구 호출 이력을 확인하고 세 가지 방책을 비교하여 하나를 선택할 수 있어야 한다.

## 2. 사용자 — 초안 제안

| 사용자 | 목적 |
| --- | --- |
| 상황 분석 사용자 | 객체와 변화를 확인하고 자연어로 분석 요청 |
| 의사결정 사용자 | 분석 근거를 검토하고 세 방책을 비교·선택 |
| 데모 운영자 | Mock C4I에서 객체 이동과 상태 변경 이벤트를 발생시켜 통합 흐름 시연 |

PoC에서는 한 명이 모든 역할에서 수행한다. 

## 3. 구성과 범위

| 구성 요소 | 제품 관점의 책임 |
| --- | --- |
| Mock C4I | 외부 체계를 모사하며 객체, 이동, 상태 및 이벤트의 원천 데이터 제공 |
| MCP Server | Agent가 C4I 정보를 도구로 조회할 수 있는 인터페이스 제공 |
| Analytical AI Platform | 상황판, 자연어 질의, 자동 분석 결과, 실행 이력, 방책 비교·선택 UI 제공 |
| 단일 분석 Agent | native tool calling과 Agent loop로 상황 인지·변화·위험 분석·방책 추천 수행 |

상황판의 실시간 데이터 전달 경로와 Agent의 MCP 조회 경로는 아키텍처 단계에서 구체화한다. 상황판의 모든 갱신이 MCP를 통하도록 요구하지는 않는다.

### PoC 제외 범위 — 초안 제안

- 실제 C4I 운영망 및 실전 데이터 연동
- 선택한 방책에 따른 C4I 명령 전송 또는 자동 실행
- 대규모 동시 사용자, 운영 수준의 고가용성 및 다중 기관 권한 관리
- 별도 모델 학습과 군사적 분석 정확도 인증
- 멀티에이전트 조율·위임, 장기 대화 메모리와 일반화된 Agent 프레임워크

### 구현 언어와 경계

- 프론트엔드 외 구현은 Python으로 한다. Mock C4I·MCP Server/Client·API·시뮬레이션·지리 계산·Agent loop·작업 큐·저장소 접근을 포함한다.
- 브라우저 UI만 React·TypeScript로 구현한다. Node/npm은 프론트엔드 빌드·개발에 한정하며 운영 백엔드에 두지 않는다.
- Mock C4I는 빌드된 자체 UI를 포함한 Python 배포물로 제공하여 플랫폼·MCP·LLM·Node 없이 실행 가능해야 한다.

## 4. 핵심 사용 흐름

1. 데모 운영자가 Mock C4I에 모의 객체를 준비한다.
2. 분석형 AI 상황판에서 동일한 객체를 확인한다.
3. C4I 객체가 이동하거나 상태가 변경되면 상황판이 갱신된다.
4. 사용자가 자연어로 질의하면 하나의 분석 Agent가 필요한 Tool을 선택하고 MCP로 C4I 정보를 조회한다. 조회 결과에 따라 추가 호출하거나 답변한다.
5. 사용자는 분석 결과와 함께 도구 호출 이력 및 근거 데이터를 확인한다.
6. 자동 분석 대상 C4I 이벤트가 발생하면 사용자 질의 없이 Agent 분석이 시작된다.
7. 방책 추천 결과를 세 개의 열에서 비교하고 하나를 선택한다.

## 5. 기능 요구사항과 수용 기준

### FR-01. 외부 C4I 객체 표시

- Mock C4I가 제공하는 객체를 분석형 AI 상황판에 표시한다.
- 동일한 객체를 양쪽 화면에서 식별할 수 있어야 한다.
- 두 상황판은 실제 지리 배경 지도를 제공하고 적군·아군 객체를 지리 좌표에 표시한다. 소속과 운용 상태는 서로 다른 속성으로 관리한다.
- R7 기본 데모는 남북 접경의 서부·중부·동부와 양쪽 연안 전반의 합성 객체 120개다. 실제 부대 배치 자료를 사용하지 않는다. 전체 보기·시연 구역 이동을 제공하며 두 UI의 시나리오 표시와 객체 수가 일치해야 한다.
- 객체는 탱크·함정처럼 유형을 구분하며 소속·유형·운용 상태·가용 상태를 각각 확인할 수 있어야 한다.
- 초안 제안: 객체 선택 시 식별자, 위치, 이동 방향, 속도, 상태, 원천 데이터 갱신 시각을 확인한다.

**수용 기준:** 준비한 아군·적군 모의 객체가 두 지리 지도에 구분되어 표시되고 식별자·소속·경도·위도를 대조할 수 있다.

### FR-02. 벡터 기반 객체 이동

- C4I 객체는 위치와 이동 벡터를 가지며 매초 이동 방향과 속도에 따른 위치 변화가 반영된다.
- 분석형 AI 상황판에서도 해당 객체의 이동을 확인할 수 있다.
- 객체는 벡터 심벌과 방향 화살표·이동 벡터로 렌더링한다. 지도 확대·축소·회전 후에도 위치와 지리적 이동 방향이 일치해야 한다.
- 아키텍처의 제안 계약은 WGS84 경위도와 동·북 방향 m/s 속도 벡터다. 세부 이동 계산·표시 길이는 설계 문서에서 관리한다.

**수용 기준:** 일정한 벡터를 설정한 객체의 위치가 연속된 초 단위로 변화하고, 두 상황판의 위치가 같은 원천 상태를 반영한다.

### FR-03. 상태 변경 실시간 반영

- C4I의 객체 상태 변경을 분석형 AI 상황판에 자동 반영한다.
- 화면을 새로고침하지 않아도 변경을 확인할 수 있어야 한다.
- 초안 제안: 연결이 끊기거나 데이터가 오래되면 마지막 갱신 시각과 함께 상태를 표시한다.

**수용 기준:** Mock C4I에서 상태를 변경하면 새로고침 없이 상황판에 동일한 상태가 표시된다. 허용 지연은 아키텍처의 성능 목표 제안을 검토하여 확정한다.

### FR-04. 자연어 질의와 MCP Tool 조회

- 사용자는 자연어로 상황 정보와 변화에 대한 질의를 입력할 수 있다.
- Agent는 필요한 C4I 정보를 MCP Tool로 조회하고 결과를 바탕으로 답변한다.
- 초기 LLM Provider는 OpenAI GPT API를 사용한다. 구체 모델 ID는 설정으로 선택한다.
- 초안 제안: 조회 실패나 데이터 부족 시 한계를 표시하고, 조회되지 않은 정보를 확인된 사실처럼 제시하지 않는다.

**수용 기준:** C4I 정보가 필요한 데모 질의에 대해 실제 MCP Tool 호출·응답이 기록되고 해당 응답에 근거한 답변을 확인한다.

### FR-05. C4I 이벤트 기반 자동 분석

- 자동 분석 대상으로 정의한 C4I 이벤트가 발생하면 사용자 질의 없이 Agent를 실행한다.
- 분석 결과에서 실행을 유발한 이벤트를 식별할 수 있어야 한다.
- 대상 이벤트와 연속 이벤트 처리 정책은 Design 단계에서 확정한다. 매초 위치 갱신이 모두 분석을 유발하는지는 별도 결정한다.

**수용 기준:** 데모 이벤트를 발생시키면 별도의 사용자 입력 없이 분석이 시작되고, 해당 이벤트와 연결된 결과가 생성된다.

### FR-06. 실행 과정과 근거 확인

- 질의 및 이벤트로 시작된 분석의 진행 상태와 결과를 확인할 수 있다.
- Agent loop의 호출 순서, 도구명, 호출 입력, 응답 또는 오류, 실행 시각, 근거 데이터를 확인할 수 있다.
- 결과에 사용된 데이터의 식별자와 조회 시각을 추적할 수 있어야 한다.
- 표시 대상은 도구 호출과 관찰 가능한 작업 기록, 근거 및 결과 요약이다. 모델의 비공개 내부 사고 과정은 요구하지 않는다.

**수용 기준:** 분석 결과에서 원인 질의 또는 이벤트, loop 실행 이력, MCP 호출 및 사용한 근거 데이터까지 따라가 확인할 수 있다.

### FR-07. 단일 동적 분석 Agent와 최소 멀티턴

- 하나의 분석 Agent가 상황 인지·변화 분석·위험 검토·방책 추천을 수행한다. 별도 Orchestrator와 전문 Agent는 이번 PoC 범위에서 제외한다.
- OpenAI native tool calling으로 도구 호출 여부·종류·순서를 동적으로 결정한다. 정해진 조회 순서나 텍스트 기반 행동 파싱에 의존하지 않는다.
- Tool 호출→결과 관찰→추가 호출 또는 최종 답변의 Agent loop를 수행한다.
- C4I 조회가 필요 없는 질문은 도구 없이 답변할 수 있다. 현재 C4I 사실은 실제 MCP 조회 근거를 사용한다.
- 멀티턴은 최근 사용자 질문·완료 답변을 전달하는 정도로 제공한다. 후속 질의는 새 run으로 처리하고 현재 상황은 다시 조회한다.
- 하네스는 모델 호출·Tool 검증/실행·최근 대화·기록·실행 제한만 담당한다. 위임·계획 버전·장기 메모리·복잡한 컨텍스트 전달 계층은 만들지 않는다.
- 오류·반복·실행 예산을 제한하고 미허가 Tool은 실행하지 않는다.

**수용 기준:** 직접 답변, native 함수 호출, 조회 결과에 따른 추가 Tool 호출, 후속 질의의 맥락 유지, 최신 데이터 재조회, 제한에 따른 loop 종료를 검증한다. 실제 단일 Agent 실행 이력과 MCP 근거를 확인한다. 상세는 [AGENT_DESIGN.md](./AGENT_DESIGN.md)를 따른다.

### FR-08. 세 가지 방책 비교와 선택

- 분석 Agent는 방책 추천 요청에 대해 한 번의 결과로 서로 구분되는 세 가지 방책을 제공한다.
- ChatGPT의 응답 비교 경험과 유사하게 세 방책을 각각 독립된 열에 나란히 표시한다.
- 사용자는 하나를 선택하고 선택 상태를 확인할 수 있다.
- 초안 제안: 각 열에 제목, 요약, 근거, 기대 효과, 위험·제약을 공통 형식으로 표시한다.
- 초안 제안: 선택은 해당 분석 실행에 연결하여 기록하며 C4I 동작을 변경하지 않는다.

**수용 기준:** 방책 세 개가 세 열에 표시되고 각각의 내용을 비교할 수 있다. 선택은 해당 응답(runId)에 귀속되며 원래 채팅에 표시된다. 후속 대화에서도 과거·최신 응답의 방책을 각각 선택·변경할 수 있다. 같은 대화의 질문·답변을 시간순으로 유지하고 선택한 방책을 다음 질의의 맥락에 포함한다. 새로고침·이력 열기로 대화를 복원하며 새 대화는 별도로 시작한다.

### FR-09. 객체 유형·가용 장비 조회와 수량 분석

- 유형은 탱크·함정·장갑차·지원 차량·무인기와 미분류를 지원한다. 추가 속성은 세부 유형·부대·정비 상태·관측 시각·출처이며 미제공 값은 미상으로 구분한다. 가용성·정비 상태·운용 상태는 독립적으로 조회한다.
- 가용·가용 불가·미확인은 원천 데이터의 별도 속성으로 관리한다. 이동 중이거나 active라는 이유만으로 가용을 판단하지 않는다.
- 상황판과 MCP에서 소속·유형·가용 조건을 함께 필터링한다.
- Agent는 `가용 아군 탱크 조회`, `적 탱크 수`, `함정의 가용 상태별 수`를 자연어로 처리하고 적용 범위·근거 시각을 설명한다.
- 개수는 해당 snapshot·조건에 일치하는 서버 집계를 사용한다. 등록되지 않은 실제 전력까지 존재한다고 추정하지 않는다.

**수용 기준:** 같은 snapshot에서 가용 아군 탱크 목록과 적 탱크 수가 원천 데이터와 일치한다. 함정은 탱크 수에 포함되지 않으며 가용 미확인·0건·페이지 제한을 구분한다. C4I 가용 상태 변경 후 새 조회와 UI에 변경이 반영된다.

## 7. UI 요구사항

- 상황판: 객체 위치·이동·상태와 데이터 갱신 상태를 확인한다.
- 질의 영역: 자연어 질문, 실행 상태, 답변과 근거를 확인한다.
- 이벤트·분석 이력: 자동 실행 원인과 실행별 결과를 탐색한다.
- 실행 상세: 단일 Agent loop와 MCP 도구 호출 기록을 확인한다.
- 방책 비교 영역: 세 열의 방책과 각 선택 버튼, 현재 선택 상태를 표시한다.

화면 배치, 색상, 지도 표현 방식과 상세 상호작용은 `UI_GUIDE.md`에서 구체화한다. 세 방책의 동시 비교를 위해 데스크톱 화면 우선을 제안하며 최소 지원 해상도는 미정이다.

## 8. 품질 요구사항 — 초안 제안

- 최신성: 원천 데이터 시각과 조회·반영 시각을 구분하여 변경 지연을 확인할 수 있어야 한다.
- 일관성: 이동 중인 객체를 분석할 때 사용한 데이터의 기준 시점 또는 버전을 추적할 수 있어야 한다.
- 오류 가시성: C4I 연결 실패, MCP 호출 실패, Agent 실행 실패를 구분하여 표시한다.
- 재현성: 같은 초기 모의 데이터와 이벤트로 주요 데모 흐름을 다시 실행할 수 있어야 한다.
- 실패 처리: 조회·분석 실패를 성공으로 표시하지 않는다. 정보 부족은 부분 결과·명확화 요청으로, 실행 오류는 실패·재시도 상태로 구분한다. 유효한 방책 세 개를 확보하기 전에는 완성된 비교 화면을 공개하지 않는다.
