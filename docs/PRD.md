# PRD — Agentic Battlefield Intelligence Platform

## 목표와 가설

합성 육군·해군 C4I와 군수 체계 → Data Fabric(Ontology·Semantic Layer·MCP) → 분석형 AI를 End-to-End로 연결한다. 모든 데이터를 조회할 수 있는 LLM이라도 체계별 형식과 군 조직·보고·절차의 의미를 일관되게 해석하기 어렵다는 문제를 검증한다. A 원천 데이터, B 원천+Fabric 문서, C 원천+구조화 지식을 비교한다. A↔B는 제공된 도메인 지식 접근의 효과, B↔C는 같은 지식 범위의 구조화·의미 조회·규칙 평가 체계의 효과다. Graph 저장 형식만의 효과로 일반화하지 않는다.

단순 집계뿐 아니라 객체 식별, 조직 범위, 상태·정책, 보고 계보·정정, 절차 진행을 다룬다. OFF 오답이나 ON 우위를 전제하지 않는다. 현재 구현·검증 한계는 [IMPLEMENTATION_STATUS](IMPLEMENTATION_STATUS.md), 기술은 [ARCHITECTURE](ARCHITECTURE.md), 화면은 [UI_GUIDE](UI_GUIDE.md)를 따른다.

## 산출물과 사용자 흐름

1. Mock ATCIS: 지상 장비·조직·보고·일지·활동, 독립 UI/API/DB/시뮬레이터.
2. Mock KNCCS: 자군·접촉·항적·편성·전문·ACK·식별 참조, 독립 UI/API/DB/시뮬레이터.
3. Mock LOGISTICS: 군수 자산·정비 작업·부품·재고/예약·보급 요청·화물, 독립 UI/API/DB/시뮬레이터.
4. Data Fabric: catalog·수집·분석 기준, 독립 지식 문서 catalog, Ontology/검증된 매핑/Graph, 원천 MCP·Knowledge MCP·Semantic MCP.
5. 분석 플랫폼: 실제 지도·적아 객체·이벤트, 자연어 질의, 단일 동적 Agent, 근거·이력·A/B/C 비교.

모의 참모/분석자는 원천에서 기록·상태를 바꾸고 플랫폼 갱신을 확인한다. 질문이나 분석 대상 이벤트가 run을 만든다. Agent는 필요한 도구를 반복 선택하거나 직접 답변한다. 사용자는 요약·규칙·근거·호출·한계를 확인하고 요청 시 세 방책을 비교·선택한다.

실제 내부 체계가 아닌 가상 스키마·합성 연습 데이터다. 실전 명령 실행, 교리 인증, 범용 문서 자동 지식화, 다중 Agent, 대규모 운영 제품은 범위 밖이다.

## 발표 메시지와 v6 지식 계층

발표 메시지: **"같은 지식이라도 지식베이스(온톨로지·지식그래프)로 구조화하면, 더 일관되고, 추적 가능하고, 바꾸기 쉬운 답을 얻는다."** ① 일관성은 반복 평가로 측정하고, ② 추적 가능성과 ③ 변경 용이성은 시연과 측정으로 보인다. "LLM은 지식베이스 없이 못 한다", 규모에 따른 효용, Graph 저장 형식만의 효과는 주장하지 않는다. A/B의 올바른 답은 유효하다. C′(원시 의미 도구만) 조건은 두지 않으므로(사용자 결정) B↔C 차이는 선언적 온톨로지·지식그래프·업무 질의 계층 전체의 효과로만 보고한다. 이번 데모는 소규모만 다룬다.

v6는 v5 원천 데이터를 그대로 쓰고 지식 계층만 바꾼다(계획의 새 원천 dataset 대신 원천 변경 위험을 피한 결정; v5 원천에 공동지원·미상·정정 보고 등 함정 자산이 이미 있다). B와 C는 같은 선언에서 생성된 같은 지식 집합을 읽는다. B는 렌더링 문서로 정의를 직접 적용하고, C는 같은 정의를 실행한 업무 질의와 원시 의미 도구를 쓴다.

시연 흐름: (1) 같은 질문을 A/B/C로 실행하고 C 답변의 근거 추적을 펼쳐 Fabric 그래프로 이동한다. (2) Fabric "온톨로지 정의"에서 기본 가용 집계 기준을 P1(가용만)→P2(제한 포함)로 바꿔 영향 분석과 업무 질의 전후 미리보기를 확인하고 다른 승인자가 발행한다. (3) 새 대화에서 같은 질문을 하면 C 답이 새 정의를 따르고, B 문서도 새 기준을 서술하며, 이전 대화와 이전 Graph는 원래 버전을 유지한다.

| 포함 | K1 1사단 가용 전차, K2 L-T02 정비·부품·수송 연결, K9 L-C01 필요 기록 | 업무 질의 선택·해석, 비확정 유지, 비용 |

## 평가

현재 객체 상세는 원천 상태·소속·제약, 정비 소요 시간과 부품, 재고·예약, 관련 수송, 정보 시점을 우선 표시한다. `laborHours`는 현재 계약의 경과 시간(h)이며 인시로 바꾸지 않는다. 도착 예정만으로 복구 완료를 확정하지 않는다. C의 공통 메타데이터는 B가 읽을 수 있는 같은 문서에 대응하며 A에는 추가 지식을 주지 않는다. 미정의 코드·정보 없음·미확정 동일성을 임의 해석하지 않는다.

상황판은 지상5+등록 함정2+접촉3의10개 원천 관측과 검증된 고유 자산 수를 구분한다. C의 의미 보기는 검증된 동일성으로 관측을 묶으며 여러 위치는 모두 유지한다.
